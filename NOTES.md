# Handoff notes

Last updated 2026-11-25. Everything needed to pick the project up on another computer.

## Goal

A **functional G5 Universal Display for FS25**, running on an iPad next to the gaming PC, that looks
like the real Deere G5 and works with live game data. Deere is a licensed brand in FS25. This is a game
mod companion, not real-machine CAN work.

## Architecture

- **FS25 mod** (`G5Link/mod/FS25_G5Link/scripts/G5Link.lua`). FS25 mods have no sockets, so it is file
  based. Every 250 ms it writes `modSettings/FS25_G5Link/telemetry.xml`, and it polls `commands.xml`
  every 250 ms.
- **Bridge** (`G5Link/bridge/g5link-bridge.js`): Node 18+, zero dependencies.
  - Polls the telemetry file, parses it and pushes JSON to browsers over Server-Sent Events (`/api/events`).
  - Writes taps (`POST /api/cmd`) to `commands.xml` with increasing ids; the mod ignores ids it has already run.
  - Serves the web app, and has a `--demo` simulator.
- **Display app** (`G5Link/app/`): plain HTML/CSS/JS, a fixed 1280×720 canvas scaled to fit (the G5
  frame is 960×540, so this is ×4/3). It can be added to the iPad Home Screen as a full-screen web app.
  - `app.js`: pages, shortcut bar, windows, commands, units.
  - `guidance.js`: the Guidance page (track math, lightbar, map canvas).

### Run pages

1. **Guidance**: lightbar, perspective/top-down map, AB tracks, coverage, Set Track, Shift Track, Location.
2. **Tractor**: overview tiles (speed, rpm, gear, load, fuel, DEF), cruise, first implement with sections, heading, work totals.
3. **Work Monitor**: 9 tiles, recording state, counter reset.
4. **Implement Details**: per implement position, drive, width, sections, fill levels, Turn On/Off.
5. **Machine Monitor**: 12 tiles.
8. **Planter**: Realistic Seeder data (Placement API v2, `g_currentMission.realisticSeederAPI`), only with a seeder implement.
7. **Field**: soil (Realistic Soil & Fertilizer), ground (Mud System Physics) and AI driver (Courseplay, AutoDrive).
9. **Harvest Automation** (combines): Speed Automation state and keys, trends, unloading.
10. **Tillage** (tillage tools): TruSet-style depth set point, presets and levels.
6. **Harvesting**: combine grain tank. With Realistic Harvesting (RH) it adds yield, moisture, throughput, grain loss by cause, engine load against target, recommended speed, the harvest settings against RH's optimum, and field totals.

Plus a full-screen **Menu** (Run Pages / Applications / System tabs), Status Center, and window shades for alerts.

## Realistic Harvesting integration

[FS25_RealisticHarvesting](https://github.com/exekx/FS25_RealisticHarvesting) publishes a read-only global
`RHM_Api` (its `src/main.lua` sets `getfenv(0)["RHM_Api"]`; the API is in `src/integration/RHM_Api.lua`). G5Link
reads it in `writeRealisticHarvesting` only if it exists, with every call wrapped in pcall, and writes `g5.rh` into the telemetry.

- Units from RH: yield t/ha, throughput t/h, area ha/h, speed km/h, moisture and loss %, engine load % (can exceed 100).
- Harvest settings are 0–100 % of each control's range. The current settings and the optimum template share key names:
  `fan`, `rotor`, `concave`, `upperSieve`, `lowerSieve`, `feeder` (the set depends on machine type). The doc comment
  in RHM_Api.getSettings names different keys, but the code (RHM_CombineMemory.lua) uses these.
- The display maps them to the G5 Harvest Settings labels: Threshing Clearance (concave), Threshing Speed (rotor),
  Cleaning Fan Speed, Chaffer Clearance (upper sieve), Sieve Clearance (lower sieve).
- US units convert t/ha to bu/ac with a per-crop bushel weight (`LB_PER_BU` in app.js; unknown crops use 56 lb).
- **Not yet checked in game:** that `RHM_Api` is visible from G5Link's mod environment (fallback: `FS25_RealisticHarvesting.RHM_Api`).
  Look for `G5Link: Realistic Harvesting read failed` in log.txt.
- The grain tank comes from vanilla `spec_combine.fillUnitIndex` (verified in the LUADOC), so it works without RH.

## Other mods through the FieldPath provider adapters

The registry and adapters from FieldPath Private Integration 0.1.0.0 (kevin7898/Fieldpath-integration) are in
`G5Link/mod/FS25_G5Link/scripts/providers/`, unchanged apart from a header line. `Providers.lua` is the host, adapted
from `FieldPathPrivateIntegration.lua`:

- If `g_currentMission.fieldPathPrivateAPI` already exists (the private integration or a FieldPath build is installed),
  G5Link reads it and installs nothing of its own. Otherwise it installs the adapters, and publishes its own
  `fieldPathPrivateAPI` only if none exists.
- Adapters: Realistic Soil & Fertilizer, Courseplay, AutoDrive (vehicle state, not the road graph), Mud System Physics.
  Realistic Harvesting is left out because G5Link reads its official `RHM_Api` (see above).
- The mod writes `providers.json` once per second (`getDisplayFrame`, minus course and field geometry) and
  `course.json` only when the Courseplay course changes (waypoints as `[x, z, flags]`, at most 4000, plus the field boundary).
  Files are written with `createFile`/`fileWrite`/`delete` (Giants API, as in BitmapUtil). JSON comes from `scripts/Json.lua`.
- The field id comes from Realistic Soil & Fertilizer's `soilSystem.hookManager:getFieldIdAtWorldPosition`. Without that mod,
  only the farmland is shown.
- The bridge merges `providers.json` into every frame (`providers`, `providerStatus`, `field`, `courseKey`) and serves
  `course.json` at `/api/course`. The Status Center lists which mods were found.
- **Not yet checked in game:** all of the above. The adapters were reviewed against Soil & Fertilizer 2.4.6.0, AutoDrive 3.0.1.2,
  Courseplay 8.1.0.3 and Mud System Physics 1.2.3.0. The installed Soil & Fertilizer is 2.6.0.3 and AutoDrive is 3.0.1.4.
  Look for `G5Link: providers ready` and `provider write failed` in log.txt.

## Map layers (bridge/coverage.js, app/layers.js)

- The mod writes each implement's main work areas with world corners (`implement(i).area(j)#sx,sz,wx,wz,hx,hz`), using
  the start/width/height nodes as WorkArea.lua reads them. Auxiliary and non-AI areas (ridge markers) are left out.
- The bridge sweeps the start-to-width edge of active areas between frames into quads, merges neighbouring sections,
  and keeps a 1 m grid per operation. A cell painted in a different pass is overlap. A new pass starts after a turn
  of more than 100°, a lift or a jump.
- Each swath carries the values of that moment: speed; yield, moisture and loss (Realistic Harvesting); rate, skips,
  doubles, singulation, CV, depth, soil moisture, compaction and yield potential (Realistic Seeder); soil N/P/K/pH
  (Soil & Fertilizer); as-applied L/ha from the tank level when no seeder data exists.
- Saved as NDJSON per savegame (`game#save` = savegame folder name) and operation; reloaded on bridge start.
- API: `/api/map/ops`, `/api/map/frames?op=&since=`, `/api/map/overlap?op=`, `POST /api/map/clear`. Every frame
  carries `map: {save, current, ops: {id: [seq, overlapVersion]}}` so displays fetch only what's new.
- **Not yet checked in game:** the work-area node positions and orientation on real implements, and the 100° pass rule
  on real headland turns.

## Ops Center (app/ops/, bridge/fields.js)

- The mod writes `fields.json` (map fields from `g_fieldManager.fields`: polygon from `getPolygonPoints()` nodes,
  `areaHa`, `farmland.id`, owner from `g_farmlandManager:getFarmlandOwner`) when anything changes, checked every
  10 s, and `equipment.json` every 5 s (motorized vehicles of the player's farm from `vehicleSystem.vehicles`).
- The bridge keeps fields per savegame in `maps/<save>/ops-fields.json`: versioned boundaries with a source (game,
  driven, coverage). The newest driven or coverage version is active unless the operator picks one. A boundary with
  no field id lands in the game field its centre lies in, unless "New Field" was chosen.
- Records are computed when asked from the recorded swaths and the active boundaries (unique area on the 1 m grid).
- Expand from coverage: field interior plus covered cells outside other fields, closed by 2 cells, flood-filled from
  the field, outer edge traced and simplified (1.2 m). Saving is always a separate, explicit step.
- Reference: `research/deere-ops-center-notes.md` (structure of the real Operations Center; captures local only).
- Boundary sources: game, driven, drawn (Ops map), coverage. Fields are colored by last work type (`lastWork`, sampled
  from every 10th swath, refreshed at most every 10 s while working, at once after a boundary change).
- Client name is an Ops setting; the farm name is read from `g_farmManager:getFarmById(farmId).name` (the `name`
  field is not confirmed in the LUADOC; guarded, falls back to "My Farm").
- **Not yet checked in game:** `fields.json` content on real maps (polygon node order, owner values), the farm name,
  and equipment.

## Harvest Profit and Service

- The mod writes `economy.json` every 30 s: `Farm:getBalance/getLoan/getEquity` (LUADOC) and per fill type
  `economyManager:getPricePerLiter` and `getCostPerLiter` (both used in Giants code: FillTrigger, SowingMachine,
  Motorized) plus `massPerLiter` (t/L). Price per tonne = price per litre / tonnes per litre. There is no documented
  per-station selling price, so the operator can set a price per crop.
- P&L in `bridge/fields.js` `profit()`: revenue from harvest records, seed from `seedLph` (Realistic Seeder
  `nominalLitersPerHa`), fertilizer/chemical from application records' L/ha and the product cost, machinery and rent from
  per-savegame settings (`settings.profit`). Anything that can't be priced is listed as "Not counted".
- Advanced Damage System: `equipment.json` carries `ads: {state, hours, interval}` read through the surface VDTelemetry
  uses (checked there against ADS 0.10.0.3): `spec_AdvancedDamageSystem`, `getIsADSExcluded()`,
  `getServiceIntervalElapsedHours()`, `getServiceInterval()`, `spec.currentState` via `ADS.STATUS`. Condition is
  deliberately not read. Checked against the v0.12.1.3 release zip (its modDesc says 0.12.1.5): all of these exist,
  `STATUS` is READY / INSPECTION / MAINTENANCE / REPAIR / BROKEN, and the service functions return operating hours.
  The repository branches are still 0.9.x; only the release zip has current code.
- Farm Finance (your FS25_FarmFinance, API 1.0.0 in its API.md): `g_currentMission.farmFinanceAPI`, read only:
  `getCreditScore`, `getInputAccount`, `getLandContract(farmlandId)` for every field's farmland. In the P&L a cash lease
  ("in") replaces the rent setting (split over the farmland's fields by area); a crop share keeps (1 - landownerShare) of
  revenue and (1 - inputShare) of seed, fertilizer and chemical (both fractions, as FFCropShare uses them). Machinery
  loans and leases come from its full read API (`getFarmSummary`, `getMarket`) on the Harvest Profit Finances tab,
  and each machine's loan or lease (matched by `uniqueId`) shows on the Equipment list.
- Due soon = 85 % of the interval; past due = 100 % (ADS's own service lamp threshold).

## Data Sync and Work Setup

- Tracks: `ops-fields.json` `tracks` ({id, name, fieldId, how, ax, az, h, at}); API `GET/POST /api/ops/tracks`
  (add, update, delete). The display reloads them when `ops.fields` (the store version) changes, keeps the selected
  track id and the last track per field in its settings, and migrates old local tracks once (`G.migrated`).
- Work Setup: `workSetup` in the same file; `GET/POST /api/ops/work-setup`; sent on every frame as `workSetup`.
  The coverage recorder uses its crop (when the machine has none) and its variety (operation id `seeding:<crop>:<variety>`).
  A fixed field in Work Setup overrides the field under the machine for tracks and the Location module.

## Shortcut keys, Harvest Automation, Tillage (scripts/Controls.lua)

- Commands: `pipeToggle` (Pipe.actionEventTogglePipe on the first child with `spec_pipe.numStates > 1`),
  `foldToggle` (Foldable.actionEventFoldAll on the first child with folding parts), `lightsToggle`,
  `beaconToggle`, `hazardToggle` (the Lights action events), `workLightsToggle` (front and back work-light bits
  together through `setLightsTypesMask`, after `getCanToggleLight`). All checked against the LUADOC
  (umbraprior/FS25-Community-LUADOC). Telemetry: `g5.controls` (lights, workFront, workBack, beacon, hazard,
  `pipe#open/state/target/states`, `fold#unfolded/moving/name`).
- Harvest Automation: `harvestAuto` (1 on, 0 off, -1 toggle), `harvestAutoMax` (km/h). Every second, while cruise
  control is active, the combine is turned on, RH says it is actively harvesting and no AI drives, cruise speed moves
  at most 0.5 km/h toward `RHM_Api.getRecommendedSpeed` (clamped 1 km/h to max). Without RH it nudges speed to hold
  95 ± 4 % engine load. Turns off when you leave the vehicle. Telemetry `g5.harvestAuto#on/state/target/max/source`.
- Tillage type from specs: `spec_plow`, `spec_cultivator` (isSubsoiler, isPowerHarrow, useDeepMode), `spec_mulcher`,
  `spec_roller`, `spec_weeder`. A cultivator that can switch level stays type `cultivator` so its map isn't split.
- Levels (TruSet-style): 2 shallow, 3 normal, 4 deep, the same numbers as **Cultivator Settings**
  (jason0611/FS25_CultivatorSettings, read from source): with `spec_CultivatorSettings.useWorkModes` the level maps
  to a WorkMode state through `workModeMapping` and goes through `setWorkMode`; otherwise (config 5) `spec.mode` is set
  and `raiseDirtyFlags(spec.dirtyFlag)` is called like its TOGGLE; config 2–4 means the shop configuration fixed the
  level (locked). Without that mod, vanilla `spec_workMode` states with `useDeepMode` false/true give shallow/normal.
  `tillageDepth` (cm) sets every tool: Realistic Tillage tools take the cm, cultivators take the level for it
  (≤ 10 shallow, ≤ 22 normal, else deep). `tillageLevel` sets a level directly.
- **Realistic Tillage** (kevin7898/Field-Path-Command `exporter/scripts/RealisticTillage.lua`, prototype 0.0.19):
  read `vehicle.spec_realisticTillage` (depthCm, targetDepthCm, min/max, depthLimited, implementClass) and call
  `vehicle:rtSetTillageDepth(cm)` / `rtChangeTillageDepth(delta)` when they exist.
- **Not yet checked in game:** all of this section; in particular that `setWorkMode` from a non-input context is
  accepted while lowered, and that Cultivator Settings' spec is reachable as `spec_CultivatorSettings`.

## Headland automation (scripts/Headland.lua, bridge/headland.js, app/headland.js)

- Settings per savegame in `ops-fields.json` `headland` (armed, widthMode distance|passes, width, passes, perField,
  raiseLead, lowerLead, lowerMode auto|steer|both, headSpeed, workSpeed (0 = keep/restore), useBoundary, useCoverage);
  API `GET/POST /api/ops/headland`.
- The bridge writes `headland.xml` (settings + the active boundary of the field under the machine, or the Work Setup
  field) when anything changes, and `headcov.xml` (cells worked at least once in the current operation within 150 m,
  runs per 1 m row) at most once a second while armed. The mod reads them every 2 s / 1 s and does the timing itself
  every 100 ms, so bridge latency doesn't move the lift point.
- Mod: front edge of the first lowerable implement's main work areas; three points across it (−30 %, 0, +30 % of the
  width) projected `speed × lead` ahead. Raise when 2 of 3 are headland/outside **and** the front edge itself is still on
  work ground (hysteresis); lower when 2 of 3 are work ground after the front edge has been in the headland. States
  work, headland, manual (lifted by hand), ai, noImplement, off. Raise/lower via
  `attacher:handleLowerImplementByAttacherJointIndex(attacher:getAttacherJointIndexFromObject(impl), down)`.
- Steering helpers (read from source/LUADOC): base game `spec_aiAutomaticSteering` (`getAIAutomaticSteeringState`,
  STATE ACTIVE/AVAILABLE, `lastDistanceToEnd` from the look-ahead point, look-ahead = max(4, xml) + (v/30)²·5);
  Enhanced Vehicle `vehicle.vData` (`is[5]` snap, `is[6]` on track, `track.eofDistance` from the vehicle to its
  headland line, `track.isOnField` > 5 = back in the field). Engage edges and EV's re-entry lower in steer mode.
- **Not yet checked in game:** that `handleLowerImplementByAttacherJointIndex` works without input focus on every
  attacher (front, rear, trailed); whether the base game line end is the tool's or the tractor's (assumed tool, from
  AI work lines); EV's fields on the current release; lead times on real hitches.

## RTK package (scripts/Rtk.lua, scripts/Api.lua, app/starfire.js, Ops Center RTK page)

- Levels NONE/SF1/SF2/SF3/RTK: Ornstein-Uhlenbeck error per axis (sigma 0.80/0.086/0.029/0.017/0.012 m,
  tau 600/1800/1800/1800/3600 s), sized so the 15-min pass-to-pass 95 % change matches 1.5 m/15/5/3/2.5 cm.
  Pull-in from SF1: SF2 2 min, SF3 4 min, SF-RTK 5 min (real time); RTK fix 10 s, error snaps to 10 %.
  The offset is added to telemetry vehicle x/z, work-area geometry and Headland.lua's points, so coverage,
  boundaries, guidance and lift points all see it. The vehicle itself is never moved.
- Receivers SF6000 (default) / SF7000 (upgrade, SF-RTK). Subscriptions monthly per machine: SF2, SF3 (covers
  SF2), MRTK, SFRTK. One-time: RTK activation, SF7000. RTK-X 14 game days.
- Base stations = placeables with "rtk" / "base station" in getName() or configFileName (placeableSystem.placeables),
  scanned every 5 s; first scan marks existing ones surveyed, later ones survey 120 game min; range 3 km.
  Survey times saved by placeable unique id. Shop price override: g_storeManager:getItems(), species PLACEABLE,
  price/dailyUpkeep set to BASE/BASE_UPKEEP (original kept on the item, BASE 0 restores).
- Billing: MessageType.PERIOD_CHANGED -> next update charges each machine; g_currentMission:addMoney(-x, farm,
  MoneyType "g5linkRtk" (MoneyType.register + FinanceStats.statNames, as FS25_FarmFinance does), true, true).
  API setPayer lets another mod take the money. Farm Finance 0.3.1 registers as payer (input account, then
  operating line, then cash; per farm) and cancels subscriptions on returned/sold machines. billMonth first drops
  subscriptions of machines missing from vehicleSystem. Ledger of 48 rows.
- State per savegame in modSettings/FS25_G5Link/rtk_<save>.xml; rtk.json for the bridge; "rtk" command with an
  `arg` text attribute ("action=sub;vehicle=<uid>;item=SF3;on=1", buy, gates, price). RTK commands work on foot.
- Equipment check (Rtk.lua hardwareOf): store item configurations (g_storeManager:getItemByXMLFilename(
  vehicle.configFileName).configurations[name] = items {name, price}) with vehicle.configurations[name] = fitted
  index. GPS config = name has gps/starfire/rtk/receiver/globe/guidance/autotrac/lenk, or an option names a
  receiver or brand. Option text -> NONE ("No", g_i18n configuration_valueNo, none/without/ohne...), SF7000
  (7000/7500/sf-rtk), SF6000 (6000 or plain StarFire), SF3000, else OTHER; "rtk" in it = RTK activation. A
  second GPS config with rtk in its name adds RTK. Re-read every 5 s. Shop hardware overrides G5Link's
  receiver/RTK purchases (SF7000 upgrade -> "changeInShop"). Receivers NONE/SF3000 (SF2 max, no M-RTK/SF-RTK,
  RTK-X 15 min)/SF6000/SF7000/OTHER. Option prices set in applyStorePrices -> priceGpsOptions (originals kept
  on the items as g5OrigPrice; SHOP_GPS 0 restores).
- Gates: headland SF2, grainCart SF3 (at full accuracy); Headland state "noSignal"; grain cart commands refused.
- API: g_currentMission.g5linkAPI, version 1.0.0, documented in mod/FS25_G5Link/API.md (Farm Finance conventions).
- **Not yet checked in game:** all of it; in particular MoneyType.register with G5Link's inline l10n, that
  changing storeItem.price shows in the construction menu, placeable names of the RTK station mods, and
  multiplayer (live state is per machine on the server; clients get it through telemetry only), and real

## Prescriptions and rate control (scripts/RateControl.lua, fields.js, Ops Center Field page, app/rate.js)

- Precision Farming (LUADOC ExtendedSprayer): spec = impl[ExtendedSprayer.SPEC_TABLE_NAME]; sprayAmountAutoMode,
  sprayAmountManual in [sprayAmountManualMin, Max]; setSprayAmountAutoMode / setSprayAmountManualValue.
- Realistic Soil & Fertilizer (src/SprayerRateManager.lua): g_SoilFertilityManager.sprayerRateManager get/setAutoMode,
  get/setIndex(vehicleId) into SoilConstants.SPRAYER_RATE.STEPS; vehicleId = root vehicle id (TargetApplication).
  It also has its own target AUTO (SF-73, gated) - "Auto" here just sets its auto mode.
- Prescription = grid of zone indexes from layer cell means (frames' quad centres inside the field), quantile breaks,
  rate per zone. Active one -> rx.xml (cell, origin, rows of multipliers). The mod finds the cell under the sprayer's main
  work areas (GNSS frame), turns the soil mod's auto off, and applies: S&F nearest step, PF starting level x multiplier.
- Telemetry g5.rate (system, auto, value, min/max or steps, rx, rxName, rxActive, rxRate, applied); commands rateAuto,
  rateStep. API /api/ops/rx (create, update, delete, activate).

## Coverage for every machine (fleet.xml)

- G5Link.lua writeFleet every 0.5 s: root motorized vehicles of the player's farm, not the driven one, that are AI
  (getIsAIActive) or have an active main work area; up to 16. Same blocks as telemetry under fleet.vehicle(i)
  (writeImplementsTo and writeCombine/writeRealisticHarvesting now take a base path). True positions.
- Bridge fleetFromXml + pollFleet; each machine is recorded with CoverageStore.onFrame(frame, 'm:<uniqueId>'). The
  recorder keeps track/pass state per machine (pass ids unique across machines, passSeq) and tags fleet frames with
  m = uniqueId. Only the driven machine sets the display's current operation. latest.fleet lists working machines.

## AutoTrac and Turn Automation (scripts/Steering.lua)

- Steering copies AIAutomaticSteering (LUADOC): look-ahead point in the AI root node frame, curvature 2x/(x^2+z^2),
  getSteeringRotTimeByCurvature, reverser inversion, min/maxRotTime clamp, getAISteeringSpeed rate limit; the vehicle's
  updateVehiclePhysics is wrapped per vehicle (axisSide from the value, rotatedTime = value) and setSteeringInput is
  wrapped so steering by hand disengages (same rules as the base game). Look-ahead 4-12 m with speed.
- Track from the display via POST /api/guidance -> guidance.xml (track ax/az/h, spacing, shift, turn on/skip/dir/radius).
  Pass k = round((dot(P-A, right) - shift) / spacing), locked at engage, re-acquired on a track/shift change.
  Steers the believed position (true + G5LinkRtk.offset), so receiver error moves the real line.
- Lets go: hand steering, AI, > 1 spacing + 1 m off, > 80 deg off, no track, no activation (G5LinkRtk.allows
  "autotrac": receiver + AUTOTRAC activation when requirements are on), Steer OFF, < 0.5 km/h for 3 s, reverse 45 s.
- Deere stages (research/deere-guidance-and-shortcuts.md): stage() 0-4 from ready()'s reason (activation/receiver/
  steerable -> 0, noTrack/aiActive -> 1), Steer OFF -> 2, else 3, engaged 4. Engage rules: Steer ON, >= 0.5 km/h,
  heading <= 80 deg (either way along the track), |xte to the nearest pass| <= 0.4 spacing; the refusal is the exit
  code (self.reason -> #last). guidance.xml carries steerOn (missing = on) and sens 50-200: look-ahead x 70/sens.
  Telemetry g5.autotrac#stage/#steerOn/#sens/#diag ("activation=1;receiver=1;...;onTrack=1").
- Turn Automation: when headland automation is in "headland" and the field edge (headland boundary) is within the room
  the turn needs (D/2 for a half circle when D = (skip+1) x spacing >= 2R, else 2R for a bulb) + 2 m, a path is built
  (half circle, or three arcs solved by bisection) and followed by pure pursuit, then the next pass k + side x s x
  (skip+1) is followed the other way. Radius: setting, vehicle.maxTurningRadius, else 7 m.
- Resume: input action G5LINK_RESUME (modDesc actions/inputBinding, Alt+R), added in Drivable.onRegisterActionEvents
  (appendedFunction, like the Grain Cart add-on does with CpHud); command "autotrac" from the display.
- **Not yet checked in game:** all of it. Watch for: the steering sign (copied from the base game, tested with a
  +x-left frame), the per-vehicle updateVehiclePhysics wrap taking effect, maxTurningRadius existing, keyboard steering
  disengaging immediately (same as the base game).
