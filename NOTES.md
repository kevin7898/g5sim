# Handoff notes

Last updated 2026-11-25. Everything needed to pick the project up on another computer.

## Goal

A **functional G5 Universal Display for FS25**, running on an iPad next to the gaming PC, that looks
like the real Deere G5 and works with live game data. Deere is a licensed brand in FS25. This is a game
mod companion, not real-machine CAN work.

## Architecture

- **FS25 mod** (`G5Link/mod/FS25_G5Link/scripts/G5Link.lua`). FS25 mods have no sockets, so it is file
  based. Every 250 ms it writes `modSettings/FS25_G5Link/telemetry.xml`, and it polls `commands.xml`
  every 250 ms.
- **Bridge** (`G5Link/bridge/g5link-bridge.js`): Node 18+, zero dependencies.
  - Polls the telemetry file, parses it and pushes JSON to browsers over Server-Sent Events (`/api/events`).
  - Writes taps (`POST /api/cmd`) to `commands.xml` with increasing ids; the mod ignores ids it has already run.
  - Serves the web app, and has a `--demo` simulator.
- **Display app** (`G5Link/app/`): plain HTML/CSS/JS, a fixed 1280×720 canvas scaled to fit (the G5
  frame is 960×540, so this is ×4/3). It can be added to the iPad Home Screen as a full-screen web app.
  - `app.js`: pages, shortcut bar, windows, commands, units.
  - `guidance.js`: the Guidance page (track math, lightbar, map canvas).

### Run pages

1. **Guidance**: lightbar, perspective/top-down map, AB tracks, coverage, Set Track, Shift Track, Location.
2. **Tractor**: overview tiles (speed, rpm, gear, load, fuel, DEF), cruise, first implement with sections, heading, work totals.
3. **Work Monitor**: 9 tiles, recording state, counter reset.
4. **Implement Details**: per implement position, drive, width, sections, fill levels, Turn On/Off.
5. **Machine Monitor**: 12 tiles.

Plus a full-screen **Menu** (Run Pages / Applications / System tabs), Status Center, and window shades for alerts.

## FS25 API facts used (and how sure)

Verified against the vendored Giants source or the community LUADOC via
[fs25-claude-skill](https://github.com/TheCodingDad-TisonK/fs25-claude-skill):

- `g_localPlayer:getCurrentVehicle()`: VehicleStateRecorder.lua
- `Vehicle:getLastSpeed()` returns km/h (`lastSpeed * 3600`): Vehicle.lua:2405
- `Vehicle:getChildVehicles()` includes the vehicle itself: Vehicle.lua:992
- `VehicleMotor:getGearInfoToDisplay()` returns gearName, available, isAutomatic, ...: VehicleMotor.lua:626
- `VehicleMotor:getDrivingDirection()`, `getLastModulatedMotorRpm`, `getMaxRpm`, `getSmoothLoadPercentage`
- `Drivable:setCruiseControlMaxSpeed(speed, speedReverse)` is nil-safe per argument; `getCruiseControlState/Speed/MaxSpeed`; `Drivable.CRUISECONTROL_STATE_*`
- `TurnOnVehicle:setIsTurnedOn`, `getIsTurnedOn`, `getCanBeTurnedOn`
- `XMLFile.create/load`, `:setInt/Float/String/Bool`, `:save()`, `:delete()`, `:iterate`, `fileExists`, `getUserProfileAppPath()`
- modDesc `descVersion` must be 90–111 (uses 104). Lua 5.1: no `goto`, no `os.*`.

**Assumed, needs checking in game:**

- `g_currentMission.environment.currentMinute` exists (the clock shows :00 if not)
- `impl.spec_workArea.workAreas` plus `getIsWorkAreaActive(wa)` for sections and the work-recording state
- `getAIWorkAreaWidth()` gives a sensible working width
- Calling the static action handlers with fake args works and syncs in multiplayer:
  `Motorized.actionEventToggleMotorState(v, "", 1, nil, false)`,
  `AttacherJoints.actionEventLowerAllImplements(...)`, `TurnOnVehicle.actionEventTurnOnAll(...)`
- `FillType.DIESEL/DEF/ELECTRICCHARGE/METHANE` and `getConsumerFillUnitIndex`
- Writing the XML file 4×/s has no noticeable performance cost, and Windows file locking between the game and the bridge is fine

## First steps on the next computer

1. Syntax-check the mod:
   ```bash
   npx luaparse G5Link/mod/FS25_G5Link/scripts/G5Link.lua
   ```
2. On the Windows PC: install Node LTS, copy `dist/FS25_G5Link.zip` to `Documents/My Games/FarmingSimulator2025/mods`,
   then run `bridge/start-bridge.bat`.
3. In FS25, enable the mod and get in a tractor. Watch `log.txt` for `G5Link` lines and Lua errors.
4. Check each item in "Assumed" above, and each shortcut key (Engine, Cruise, Lower/Raise, Turn On).

## Design reference (how the look was matched)

The look was matched to the real G5 Universal in the Deere Display and CommandARM Simulator
(displaysimulator.deere.com; needs a Deere login). The G5 screen there is a VNC canvas you can read:

```js
document.getElementById('Simulatorpageframe').contentDocument
  .getElementById('contentArea_linux').contentDocument.querySelector('canvas').toDataURL('image/png')
```

The full-resolution captures (Guidance, Planter Details, SeedStar window, ISOBUS dialog, Menu) were kept
locally for reference only and are **not committed**, since they are Deere's UI.

Sampled palette (in `G5Link/app/style.css` `:root`):

| Element | Color |
|---|---|
| Title bar, arrow keys, MENU key | `#367c2b` |
| Separators on green | `#1d4a17` |
| Page background (olive) | `#302e11` |
| Module frame | `#7d7b62` |
| Module title strip | `#413f22` |
| Tile and panel cream | `#f1efe4` / `#f5f3e1` |
| Tile top strip | `#858585` (off), `#32b04b` (on) |
| Shortcut keys | `#e1dfcf` → `#cfcdb4` on a black bar, black state strip |
| Lightbar center | `#ffee3f`; lit segment `#c40b0b` |
| Alert window shade | `#ebbfc1` with a `#f27579` border |

Layout notes: the title bar is about 45 px at 960 wide, the shortcut bar about 62 px, the side column
140 px. The Menu is full screen with left tabs (selected tab yellow with an arrow) and white app tiles
with a yellow-and-green bottom stripe. The icons in the app are original line drawings, not Deere artwork.
